# TF卡（SDIO）预研与接入计划

## 1. 硬件引脚（基于你给的图）
- `PC12` -> `SDIO_CK`
- `PD2`  -> `SDIO_CMD`
- `PC8`  -> `SDIO_D0`
- `PC9`  -> `SDIO_D1`
- `PC10` -> `SDIO_D2`
- `PC11` -> `SDIO_D3`
- `PD3`  -> `SD_CARD_DET`（卡检测，可选）

## 2. 与现有资源冲突评估
- 当前音频 I2S 用 `PC10/PC12`（BCLK/DIN）
- 因此 **SDIO 与 I2S 当前必冲突**，不能同时按现有引脚运行

### 建议方案（后续）
1. 音频改到 `I2S2` 或改为 `SPI+DAC/PWM` 路径  
2. 或仅在“文件管理模式”临时停用音频并切换 SDIO（不推荐长期）

## 3. 软件接入分层
- `drivers/sdio_tf`：SDIO 时钟/GPIO/FATFS 初始化
- `services/fs_service`：文件枚举、打开、读块接口
- `services/player_service`：优先读 TF 文件，失败回退 W25Q128

## 4. 推荐里程碑
1. **P0**：识别卡 + 打印容量与文件系统信息
2. **P1**：读取目录并在串口列出 `.pcm`
3. **P2**：播放器按文件名选曲播放（替代硬编码地址）
4. **P3**：加入缓存策略（双缓冲）降低卡顿

## 5. 关键参数建议
- SDIO 总线：4-bit
- FATFS 扇区读：`512B`（基础）+ 上层聚合到 `2KB~4KB`
- 音频播放缓存：至少 `8KB`（建议 `16KB`）

## 6. 风险与规避
- 风险：音频与 SDIO 引脚冲突
- 规避：先冻结外设资源表，再实施 TF 接入，不要边改边测

## 7. 结论
当前工程已稳定在“W25Q128 播放”方案。  
TF 卡可行，但必须先处理 `PC10/PC12` 与 I2S 冲突，再进入实现阶段。
